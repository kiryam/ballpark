# Ballpark

**[English version](README.md)**

Слепая калибровка офсетов сопел IDEX-голов для Klipper по шаровому пробу:
голова сама находит шар (без предположений о геометрии головы), фиксирует
вершину сходящимся шаблоном параболоидных фитов, верифицирует сигнатуру
купола, переключается на голову B, перемеряет и перепроверяет ревизией
головы A. Офсеты применяются через `IDEX_VARS` + `SAVE_OFFSETS_TO_DISK`.

Валидировано на физическом стенде (`tests/sim_harness.py`, портирован с
проверенного 3D-симулятора) на случайных головах, толчках шара, наводках
провода и блужданиях шара: 98.7% чистых завершений на невиданных seed,
медианная ошибка офсета **0.05 мм**, p95 0.12 мм, ноль зависаний (жёсткие
бюджеты нажатий/времени по построению). Каталог проблем v8/v9, из-за
которых сделан рерайт — в [ANALYSIS.md](ANALYSIS.md).

## Установка

### Moonraker (рекомендуется)

Добавить в `moonraker.conf`:

```ini
[update_manager ballpark]
type: git_repo
primary_branch: main
origin: https://github.com/kiryam/ballpark.git
path: ~/ballpark
install_script: install.sh
managed_services: klipper
```

Перезапустить moonraker (`sudo systemctl restart moonraker`), затем
установить из Mainsail/Fluidd → Update Manager (или дождаться проверки
обновлений).

### Вручную (на хосте с klipper)

```bash
git clone https://github.com/kiryam/ballpark.git ~/ballpark
~/ballpark/install.sh
sudo systemctl restart klipper
```

### С рабочей машины

```bash
./install.sh ваш-хост              # залить, установить, перезапустить, проверить
```

`install.sh` копирует плагин в `~/printer_data/config/ballpark/`, делает
симлинк модуля в klippy extras и вставляет `[include ballpark/*.cfg]` в
`printer.cfg` (ДО автосейв-блока `#*#`, с бэкапом).

Единственный обязательный параметр — пин проба — вписать в
`~/printer_data/config/ballpark/tool_offset_sphere.cfg`:

```ini
[tool_offset_sphere]
pin: ^endstop7
```

### Удаление

```bash
rm ~/klipper/klippy/extras/tool_offset_sphere.py
rm -rf ~/printer_data/config/ballpark ~/ballpark   # + убрать строку include
sudo systemctl restart klipper
```

## Запуск

1. Сопла чистые, лейна головы B загружена, оси огомнены. Шар — где угодно
   в зоне досягаемости головы; при самом первом запуске поставьте голову
   над ним (дальше подсказкой служит запомненная позиция).
2. `TOOL_SPHERE_CALIBRATE DRY_RUN=1` — полный прогон, офсеты не трогаются.
3. `TOOL_SPHERE_CALIBRATE` — замерить, проверить и применить.

Позиция и высота шара самообучаются каждый прогон и хранятся в
`.ball-state.json` рядом с конфигом — после любых переделок железа
перенастраивать нечего: алгоритм сам перезаправивается от собственного
замера головы A.

`TOOL_SPHERE_QUERY_PROBE` — состояние проба.
`TOOL_SPHERE_NOISE_TEST` — тряска осей, подсчёт наводок.
`TOOL_SPHERE_PROBE_TEST` — один probing_move вниз+вверх, с состояниями пина.

## Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `pin` | — (обязателен) | пин проба, напр. `^endstop7` (НЗ) |
| `ball_radius` | 5 | радиус шара проба |
| `floor_z` | 38 | ниже этого Z не жать — защита корпуса проба |
| `edge_margin` | 15 | отступ от границ осей |
| `probe_speed` / `travel_speed` / `lift_speed` | 4 / 80 / 15 | мм/с |
| `head_switch_b_gcode` / `head_switch_a_gcode` | `T1` / `T0` | смена кареток |

Плагин применяет офсеты через `SET_GCODE_VARIABLE MACRO=IDEX_VARS` +
`SAVE_OFFSETS_TO_DISK` — эти макросы должны быть определены на принтере.

## Как это работает (v10, «сходящийся шаблон»)

Одна примитива — нажатие сверху с ограничением глубины — и три яруса
глубины (top-cone / presence / cold), пользующиеся только геометрией
шара: любая голова с любыми дактами и кожухами работает без настроек.
Шаблон из 5 нажатий фитать параболоид и прыгает к вершине (Ньютон,
2-3 раунда); сам фит отбраковывает чужие поверхности, а кольцо нажатий
внутри 35-градусного конуса контакта подтверждает сигнатуру купола,
физически не имея возможности сдвинуть шар. Робастный фиат с полным
перебором выбросов игнорирует наводки; голова B и ревизия головы A
брекетируют офсет; свежий принтер повторяет пару B/A с собственной
первой оценкой до применения. У каждой петли жёсткий бюджет — отказ
это внятная ошибка, никогда не зависание.

## Тестовый стенд

```bash
python3 tests/sim_harness.py all              # сетка + регрессии + бюджеты
python3 tests/sim_harness.py debug stale_bt   # подробный одиночный случай
```

Физика: контакты по элементам головы (портировано с валидированного
3D-симулятора, удалённого из репозитория), предпрогиб рычага, люфт
считывания X/Y, глитчи считывания, сдвиги шара от нажатий в плечо,
толчки при смене головы, кольцо корпуса проба.

Проверено на железе (2026-08-26, IDEX/CAN-машина): полный цикл
A → B → ревизия укладывается в 167 нажатий / ~10 минут, повторяемость
апекса между проходами 0.02 мм; любой отказный путь (бюджеты, ворота
правдоподобия) аккуратно прерывает прогон, ничего не применяя.
